# Run a Node

Aztec is a permissionless network. Anyone can sync a node, propose blocks, or generate proofs. Pick the role that fits what you want to do, and the docs will walk you through it.

## What comes after picking a role

- The **guided setup** is opinionated and personalized: paste your RPC URLs and keys once, every command on every page auto-fills with your values.
- The **advanced operations** section in the sidebar covers everything the playbook doesn't: high-availability topologies, deep keystore management, monitoring stack, governance signalling, provider tooling.
- The **reference** section is for when you know what you're looking for: CLI flags, env vars, JSON-RPC, the Ethereum-RPC requirements.

## Using these docs with an AI assistant

These docs are published in a machine-readable form, so you can hand them to an AI assistant instead of copying pages by hand.

- `llms.txt` at [docs.aztec.network/llms.txt](https://docs.aztec.network/llms.txt) is an index of every page. `llms-full.txt` is the whole site as a single file.
- The **Copy page** button at the top of each page copies that page as markdown, ready to paste into a chat.
- Append `.md` to any docs URL to fetch the markdown source of that page.
- The [AI Tooling guide](/developers/ai_tooling) covers the Aztec MCP server and project instruction files for tools like Claude Code, Cursor, and Codex.

Always verify commands, addresses, and version numbers against these docs before you run them on a live node. An assistant can read the docs, but it cannot see your setup.
