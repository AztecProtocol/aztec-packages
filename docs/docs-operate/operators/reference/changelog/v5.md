## Breaking changes

### Archiver storage format changed — one-time resync from L1

The archiver log index has been redesigned to support tag-based queries with block-range filtering, per-tag pagination, and on-demand effect attachment. The on-disk layout for `privateLogs` and `publicLogs` is incompatible with v4, and contract-class-log storage has been removed entirely (registration discovery already reads block bodies directly).

`ARCHIVER_DB_VERSION` has been bumped from `6` to `7`. On first start with a v5 binary, the archiver detects the version mismatch, **wipes its local database, and re-syncs from L1 from scratch**. No configuration changes are required.

**Migration**: No action required. Expect a one-time resync on first start — duration depends on chain height and L1 RPC throughput. To avoid an unattended resync, you may pre-delete the archiver data directory before starting v5; behavior is identical either way.
