## Breaking changes

### Local signing protection requires a persistent data directory

Single-node validators (those not using HA signing) now refuse to start unless a data directory is
configured, so that local double-signing protection survives crashes and restarts. Previously, a
missing data directory silently fell back to a fresh ephemeral store on every start, which provided
no protection across restarts.

**Migration**: Set `DATA_DIRECTORY` so the signing-protection database is persisted to disk. For
dev/test networks where persistence is not required, opt into the ephemeral store explicitly:

```bash
VALIDATOR_ALLOW_EPHEMERAL_SIGNING_PROTECTION=true
```

Running ephemeral logs a warning at startup and is unsafe for production validators.

### Unreadable signing-protection version file now fails startup

If the signing-protection database's version file exists but cannot be read (permission error, IO
error, or a truncated/corrupted file), the node now fails startup with an actionable error instead
of silently resetting — i.e. wiping — the protection database. A genuinely missing version file
(first boot) is still treated as a normal fresh start.

**Migration**: No action required in normal operation. If startup fails with a version-file read
error, resolve the underlying filesystem problem (permissions, disk health) and restart; the
protection data is left untouched.
