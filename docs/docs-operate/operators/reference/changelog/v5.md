## Breaking changes

### `SLASH_ATTEST_DESCENDANT_OF_INVALID_PENALTY` renamed to `SLASH_PROPOSE_DESCENDANT_OF_INVALID_PENALTY`

The slashing offence for building on an invalid checkpoint has been renamed to reflect that the slash targets the proposer of the descendant checkpoint published to L1, not its attestors.

**v4.x:**

```bash
SLASH_ATTEST_DESCENDANT_OF_INVALID_PENALTY=<value>
```

**v5.0.0:**

```bash
SLASH_PROPOSE_DESCENDANT_OF_INVALID_PENALTY=<value>
```

**Migration**: rename the variable in your node environment, systemd units, helm values, or any deployment scripts. The underlying offence enum (`OffenseType`) has also been renamed from `ATTESTED_DESCENDANT_OF_INVALID` to `PROPOSED_DESCENDANT_OF_INVALID`, which only affects downstream tools that parse offence types from the slasher.
