sumcheck-webgpu (BN254 Fr, MegaFlavor)

WebGPU correctness checks diffed against CPU references: the Fr Montgomery primitives, the short-monomial (Mono) arithmetic, the relation accumulate kernels, the fold, and the full multi-round sumcheck. Pick a suite or Run All. Needs no WASM build.

Times the full sumcheck across sizes for three provers: the resident-byte multi-round WebGPU engine (per-round CPU readback for Fiat-Shamir), the single-submit WebGPU engine (GPU-derived Fiat-Shamir, whole protocol in one command buffer), and the WASM prover (bb.js bbapi SumcheckBench). All run in this browser. Each GPU engine shows GPU dispatch and end-to-end wall (the latter includes the CPU tail + decode); the ×WASM columns are WASM÷wall (>1 = GPU faster). outputs cross-checks correctness independently — the superscript is how many engines agreed (² = both GPU engines, ³ = + the CPU reference at small n; hover for the per-check breakdown). Three checks: single-submit's GPU Fiat-Shamir is re-derived on the CPU (Poseidon2) and must match; the multi-round engine, run on that verified chain, must produce the same round univariates bit-for-bit; and below 2^13 a fully independent canonical-bigint CPU reference must match too. WASM is timing-only — its bbapi reports no univariates, so it is not output-checked. The WASM column is empty until barretenberg.wasm is rebuilt with the command.

Splits the multi-round sumcheck: the first k rounds run on the WebGPU engine (the heavy front — round 0 alone is ~half the field work, and each round halves what remains), then the WASM prover finishes the remaining d−k rounds. Sumcheck is recursive, so the WASM tail is timed with SumcheckBench(d−k). Hybrid = GPU k rounds + folded-column handoff readback + WASM tail, shown against the full-WASM and full-GPU baselines. Needs ?coi=1 + a WASM build for the tail.
