BN254 WebGPU MSM — correctness vs @noble/curves

Generates n = 2log₂(n) random affine BN254 G1 points and Fr scalars, runs the MSM on the GPU via compute_bn254_msm, then cross-checks against a CPU reference computed with bn254.G1.ProjectivePoint.msm (Pippenger) from @noble/curves. A failure here means the WGSL shaders or the Montgomery marshalling are wrong — i.e. nothing downstream of the WebGPU port can be trusted. Default log₂(n) = 16 matches the C++ BBERG_WEBGPU_MSM_MIN_N threshold, so the prove-path delegation is exercised.

(n = 65536)
What this is testing

Inputs: n random G1 points generated as BASE.multiply(random_fr) via noble, and n random Fr scalars from crypto.getRandomValues.

GPU side: pack points into the [x_0|y_0|x_1|y_1|...] interleaved LE-32 layout the port expects (matches the C++ marshal_points marshalling — see webgpu_msm_marshalling.hpp), scalars into n × 32 LE bytes, call compute_bn254_msm(points_buf, scalars_buf, false).

Reference: noble's ProjectivePoint.fromAffine(...).multiplyUnsafe(s) per index, accumulated into a single projective point, then .toAffine() at the end. Comparison is on the affine (x, y) pair.
