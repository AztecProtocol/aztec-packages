Persistent Treap Forks

How wsdb-ref's PersistentKeyIndex keeps an ordered key → leaf-index map that can be forked, checkpointed and kept per block for the cost of copying one pointer.

A treap is a search tree and a heap at once

Each node carries a key and a priority. The tree obeys two orderings at the same time, and for a given set of keys and priorities only one tree satisfies both.

By key: a search tree

Smaller keys go left, larger keys go right, so find and predecessor (the indexed trees' low-leaf lookup) walk one root-to-leaf path.

By priority: a heap

A parent's priority is higher than its children's. Random priorities make the shape that of a random insertion order, so the depth stays O(log n) on average.

Priority = hash(key)

wsdb-ref uses splitmix64 of the key instead of a random number, so the shape depends only on the set of keys and every run builds the same tree.

Why an insert copies only one path

Nodes are immutable (shared_ptr<const Node>). An insert walks down from the root while the existing node's priority is higher, rebuilding each node it passes with one new child pointer. Where the new key's priority wins, it splits that subtree by key and takes the two halves as its children; the split also rebuilds only the nodes on its path. Every subtree off that path is reused as is.

So a version is just a root pointer. The old root still describes the old tree, untouched, and the new root shares everything except about log n nodes with it. Select an older version above and insert into it: that is a fork, and both branches keep sharing the nodes they had in common.

How the reference world state forks

Each of the five trees pairs a PersistentMerkleTree (built on the same path-copying idea) with a PersistentKeyIndex. Both are a root pointer, so the whole state is ten pointers:

struct Trees {
    NullifierTree   nullifier;    // tree root + key index root
    AppendOnlyTree  note_hash;    // tree root + key index root
    PublicDataTree  public_data;  // tree root + key index root
    AppendOnlyTree  l1_to_l2;     // tree root + key index root
    AppendOnlyTree  archive;      // tree root + key index root
};  // "Copying one is copying ten pointers."

From there each operation is a copy of Trees:

  • Committed blocks: keep a Trees per block, so reads at any block are direct.
  • Fork: copy the Trees of the block it starts from, then write to the copy.
  • Checkpoint: push a copy of the fork's current Trees; revert pops it back, commit drops it.

No operation copies tree contents. Writes pay O(log n) new nodes each, whichever version they write to, and memory is shared by every version that still points at it.
