- Msgpack rewrite direction: follow the upb/mini-table lesson, not the full C++ protobuf lesson. Generate compact schema tables or declarations, keep parsing/packing in one or a few `.cpp` files, and make ordinary C++ callers consume typed byte-level APIs or cheap structs. Cap'n Proto and FlatBuffers show another useful pattern: generated headers can expose lightweight readers/builders or object declarations while bulk encode/decode mechanics live behind generated implementation files. Useful references: `https://pigweed.googlesource.com/third_party/github/protocolbuffers/protobuf/+/HEAD/docs/upb/vs-cpp-protos.md`, `https://capnproto.org/cxx.html`, `https://flatbuffers.dev/languages/cpp/`.

- The research-backed target shape for a full msgpack rewrite is table-driven, not C++ reflection/template-driven. upb’s design is the clearest model: generated files emit compact schema tables and the runtime parser/serializer interprets those tables, instead of generating parse/serialize functions per type. Cap’n Proto’s C++ docs support the same compile-time principle: generated `.capnp.c++` files contain embedded schema data and avoid STL-heavy public interfaces. FlatBuffers’ mini-reflection is a useful lower-overhead schema-data pattern; it adds tiny per-field tables that generic visitors can consume. For bb, that means generated per-type metadata arrays plus hand-written/simple generated encode/decode loops, not `msgpack::adaptor`, `std::variant` megatypes, or schema construction through `std::make_unique<T>()`.
- For `bbapi`, replace the current `NamedUnion<...>`/`std::variant`/`std::visit`/msgpack-c conversion path with a generated command table: command name string, decode function pointer, execute function pointer, encode response function pointer, and schema descriptor pointer. This should avoid instantiating one giant command variant and the recursive `construct_by_index` chain in `c_bind.cpp`; current traces still show repeated 3-4s `NamedUnion<bbapi...>` instantiation events in that one TU.
- For schema generation, stop deriving JSON schema by constructing arbitrary `std::make_unique<T>()` objects through template overloads in C++. Generate schema data directly from the command/type metadata, either as constexpr tables with a tiny printer or as a generated JSON/msgpack blob. This attacks `bbapi_schema*.cpp` and avoids using runtime msgpack conversion templates to compute schema.
- For msgpack-c, aim to confine the umbrella `<msgpack.hpp>` include to a small set of implementation files. If we rewrite all msgpack, prefer a tiny internal reader/writer over msgpack-c adaptors for command payloads: explicit `read_map_field`, `read_array`, `read_bin`, `write_map`, `write_bin`, plus generated per-type functions. The goal is boring C++ functions and tables, not generic adaptor specialization.
- For Noir/ACIR, generate a public type-only/light serde header plus private decode/encode `.cpp` files or a minitable interpreter. The current type-shape experiment suggests this is the largest remaining generated-header opportunity: ~5.46s syntax-only for current `acir.hpp` versus ~0.89s for type-only/light serde.
